# MINDPRINT AI

Работающий демонстрационный MVP сопровождения между консультациями: психолог назначает упражнение, пациент общается с ИИ-компаньоном и проходит шаги, психолог видит сохранённый результат и формирует сводку с источниками.

**Все стартовые профили и записи синтетические.** По умолчанию приложение работает автономно с `AI_PROVIDER=mock`. Этот режим использует сценарные ответы и поиск тем по словам, а не нейросеть. GigaChat — отдельный внешний провайдер для встроенных синтетических примеров; его нельзя представлять как закрытый контур. Локальная Qwen3 14B — целевая конфигурация, а не уже развёрнутая модель.

## Запуск

Нужны Docker и Docker Compose v2 с поддержкой необязательного `env_file` (2.24+).

```bash
cd mindprint
docker compose up -d --build
```

Дополнительные настройки для первого автономного запуска не нужны. При запуске backend выполняет Alembic-миграции и однократно создаёт демонстрационные данные. Повторный запуск сохраняет их в PostgreSQL volume.

- Приложение: http://localhost:3000
- API: http://localhost:8000
- Swagger: http://localhost:8000/docs

Порты приложения привязаны к `127.0.0.1`. PostgreSQL доступен только внутри сети Docker. Если 3000 или 8000 заняты, поменяйте левую часть соответствующей привязки в Compose; при смене frontend-порта также обновите `ALLOWED_ORIGINS` в `backend/.env`.

```bash
docker compose ps
docker compose logs --tail=50 backend
docker compose down                 # Останавливает, сохраняя данные
```

Удаление volume очищает данные. Для чистой повторной демонстрации это возможно через `docker compose down -v`, но команда необратима — не используйте её для данных, которые нужно сохранить.

## Вход

На `/login` есть кнопки «Войти как психолог» и «Войти как пациент». Они существуют только при `DEMO_MODE=true`; сервер также проверяет этот флаг.

- Психолог: `psychologist@mindprint.demo` — Анна Смирнова.
- Пациент: `patient@mindprint.demo` — Александр.
- Дополнительно в кабинете психолога доступны синтетические Мария и Дмитрий.

Для входа по email можно до первого заполнения БД задать `DEMO_PASSWORD` в `backend/.env`. Если значение пустое, seed генерирует случайный неизвестный пароль: демокнопки работают, общего опубликованного пароля нет. Изменение переменной после заполнения БД не меняет существующие пароли.

## Демонстрационный сценарий

1. Войти как психолог, открыть Александра. График использует 14 дней сохранённых записей: стабильное начало, рабочие переживания, упоминания сна и первые упражнения.
2. При необходимости открыть «План сопровождения», изменить темы, цели и разрешённые упражнения, сохранить. Разрешение упражнения в плане и его назначение — отдельные действия.
3. Нажать «Назначить упражнение» → «Дневник мыслей» → «Назначить».
4. В верхней панели переключиться в кабинет пациента, открыть «ИИ-компаньон».
5. Нажать встроенный демонстрационный запрос либо в mock-режиме написать: «Мне снова очень тревожно из-за работы. Кажется, что начальник хочет меня уволить».
6. Компаньон учитывает актуальное назначение. Под диалогом открыть «Дневник мыслей», пройти пять вопросов. Каждый ответ сохраняется сервером; незавершённое упражнение можно продолжить.
7. Переключиться в кабинет психолога, открыть Александра → «Упражнения». Видны выполненное задание, время завершения и ответы.
8. Нажать «Сформировать отчёт». В модальном окне есть динамика, темы, число выполнений, вопросы к встрече, цитаты с идентификаторами записей. Отметить вывод как подтверждённый, некорректный или требующий обсуждения.
9. Для демонстрации приватности перейти в кабинет пациента → «Приватность», отозвать общее согласие. Пациент исчезает из списка психолога, API закрывает профиль, дневник, аналитику, отчёты, назначения и изменения плана. Согласие можно снова включить.

Изменения загружаются при переходе между кабинетами и по кнопке обновления. WebSocket/push в MVP нет.

## Возможности

- Русскоязычные адаптивные кабинеты, landing, загрузки, уведомления, модальные окна.
- История чатов, новый диалог, быстрые действия, Enter для отправки, индикатор ответа, ошибки провайдера без скрытой подмены на mock.
- Дневник: дата, настроение 1–5, текст, теги, отметки о завершённых упражнениях.
- Три упражнения: дневник мыслей, рефлексия дня, дыхательная практика на 1 или 2 минуты с паузой.
- План психолога: темы, цели, разрешённые упражнения, настройка частоты напоминания. Напоминание показывается в кабинете при включённой настройке и незавершённых заданиях. Рассылок и фонового планировщика нет; частота пока отображается как часть плана.
- Графики и сводки за 7/14/30 дней, темы с цитатами, история отчётов, обратная связь на наблюдения.
- Раздельное согласие на дневник, аналитику и упражнения. Разрешение аналитики **включает цитаты-основания из дневника** даже при отключённом просмотре полного дневника; это явно объясняется пациенту. Переписки психологу не предоставляются.
- Полное удаление аккаунта пациента и связанных данных через UI.
- Лист ожидания с уникальным нормализованным email. Повторная заявка не увеличивает счётчик и не раскрывает наличие адреса.

## Провайдеры AI

Скопируйте пример конфигурации:

```bash
cp backend/.env.example backend/.env
```

После изменения окружения:

```bash
docker compose up -d --force-recreate backend
```

### Mock (по умолчанию)

```env
AI_PROVIDER=mock
DEMO_MODE=true
```

Сценарные ответы учитывают актуальные назначения. Анализ тем основан на ключевых словах, источники — реальные сохранённые записи. Это автономный режим демонстрации пользовательского пути, не оценка качества LLM и не психологическая диагностика. Произвольный ввод работает без передачи наружу.

### GigaChat

```env
AI_PROVIDER=gigachat
DEMO_MODE=true
GIGACHAT_CREDENTIALS=ваш_ключ_только_в_локальном_env
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Pro
GIGACHAT_BASE_URL=https://api.giga.chat/v1
```

Используется официальный Python SDK `gigachat`, асинхронный `achat`, ограничение времени, проверка TLS. Для необходимого доверенного CA можно указать `GIGACHAT_CA_BUNDLE` и смонтировать сертификат в backend-контейнер. TLS-проверка не отключается. [Документация SDK](https://developers.sber.ru/docs/ru/gigachain/tools/python/gigachat).

**Серверный барьер внешней передачи:**

- Внешний чат принимает только фиксированные фразы из `app/services/fixtures.py`, только от синтетического профиля и при `DEMO_MODE=true`.
- Отредактированные темы/цели плана допускаются лишь при точном совпадении с разрешённым синтетическим набором.
- Прошлый локальный/mock-диалог нельзя продолжить во внешнем режиме: нужно начать новый. Для каждого сообщения хранится признак безопасного внешнего происхождения.
- Свободный текст дневника сохраняется локально **без отправки в GigaChat**. UI сообщает, что анализ недоступен.
- Для внешнего анализа разрешены только seed-записи с серверным признаком `synthetic` и точным совпадением текста с fixture. Клиент не может установить этот признак.
- Если в выбранном периоде есть новые свободные записи, отчёт GigaChat блокируется. Переключитесь на mock/local; данные не удаляются.
- Содержимое ключа не поступает в frontend. `.env` исключён из Git и Docker build context.

Для чемпионата с запретом внешних API используйте mock или собственный локальный инференс. GigaChat не требуется ни для запуска, ни для тестов. Проверка живого ответа GigaChat требует действующего ключа; без него интеграция проверена только на конфигурацию и обработку ошибок.

### Локальная Qwen3

```env
AI_PROVIDER=local
LOCAL_LLM_URL=http://host.docker.internal:8080/v1
LOCAL_LLM_MODEL=Qwen3-14B
```

Адаптер обращается к OpenAI-compatible `/chat/completions` локального сервера, например vLLM. Сервер, веса и GPU нужно подготовить отдельно; обучение, подбор параметров RTX 5090 и оценка качества модели не входят в эту реализацию. На Linux для `host.docker.internal` может понадобиться `extra_hosts: ["host.docker.internal:host-gateway"]` в сервисе backend. Не задавайте внешний адрес для реальных данных.

Контракт `AIProvider.chat(messages, context)` / `analyze_entries(entries)` расположен в `backend/app/services/ai/base.py`. Бизнес-логика работает независимо от провайдера.

## Лист ожидания и администратор

Форма на landing сохраняет заявки в PostgreSQL. Цель 100 регистраций — целевая метрика, не достигнутый результат; синтетические профили не считаются регистрациями.

Создать администратора без секретов в командной строке:

```bash
docker compose exec backend python -m app.create_admin
```

Скрипт интерактивно запрашивает email, имя и пароль. После входа открывается `/admin/dashboard` со статистикой `GET /api/waitlist/stats`; пациент и психолог не имеют доступа к этому endpoint.

## Архитектура

```text
Next.js App Router + TypeScript + Tailwind + Radix/shadcn-style UI + Recharts
  └── same-origin /api proxy, HttpOnly cookie
       └── FastAPI
            ├── SQLAlchemy asyncio → PostgreSQL
            ├── auth / consent / therapy / exercises
            ├── safety scenarios before LLM
            ├── evidence validation → observations / reports
            └── AIProvider → mock | GigaChat SDK | local HTTP
```

- `frontend/components/`: общие элементы, пациент, психолог, чат, landing.
- `frontend/components/ui/`: локальные shadcn-совместимые Button/Dialog на CVA и Radix; конфигурация CLI в `components.json`.
- `backend/app/api/`: HTTP endpoints и контроль доступа.
- `backend/app/services/`: план, чат, аналитика, safety, провайдеры.
- `backend/app/models/`: 12 таблиц, внешние ключи, индексы, уникальные email, ограничения ролей/настроения.
- `backend/alembic/versions/`: явная начальная миграция.
- `backend/tests/`: 15 интеграционных и сервисных тестов без внешних AI.
- `frontend/tests/demo-flow.mjs`: браузерный сквозной тест; изменяет только демоданные запущенного приложения.
- `docs/specification.md`: исходное ТЗ.
- `docs/qa/`: скриншоты проверки.

Сессии — случайные opaque-токены, в БД хранится только SHA-256 токена; срок 12 часов. Пароли — Argon2. Проверяются роли, связь психолог–пациент, общее и предметное согласие. Есть проверка Origin/Fetch Metadata для изменяющих запросов и ограничение частоты входа. Адреса и тексты не отправляются рекламным/аналитическим системам. Приложение не логирует содержимое дневников, диалогов или ответы провайдера.

## Тесты и разработка

Python 3.13+, Node.js 22+.

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
pytest -q
```

Тесты используют отдельную in-memory SQLite с той же моделью данных. Сценарий в Docker использует PostgreSQL. Для запуска локального API вместо контейнера задайте `DATABASE_URL` своего PostgreSQL; затем:

```bash
alembic upgrade head
python -m app.seed
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```bash
cd frontend
npm ci
npm run typecheck
npm run build
npm run dev
```

Frontend проксирует запросы на `BACKEND_URL` (по умолчанию `http://127.0.0.1:8000`). Для браузерного теста при запущенном Compose:

```bash
cd frontend
npx playwright install chromium
node tests/demo-flow.mjs
```

Если Chromium уже установлен отдельно, укажите путь через `MINDPRINT_BROWSER`. Скриншоты сохраняются в `docs/qa`. Браузерный тест добавляет записи и задания; повторные прогоны увеличивают счётчики.

Миграции:

```bash
docker compose exec backend alembic current
docker compose exec backend alembic upgrade head
```

## Границы демонстрационной версии

- Это демонстрационный MVP, не клинически валидированная система. Safety Engine распознаёт ограниченный набор формулировок и может пропустить кризис. Он не оповещает психолога и не заменяет экстренные службы.
- Числа аналитики вычисляются по БД. AI-наблюдения валидируются Pydantic; цитата должна дословно входить в указанную запись. Это проверяет источник цитаты, но не медицинскую достоверность вывода.
- Нет публичной регистрации пациентов, восстановления пароля, многофакторного входа, background job queue, уведомлений по email/push и продуктовой эксплуатации реальных медицинских данных.
- Напоминания работают как подсказка в кабинете; сохранённая частота не является расписанием внешней доставки.
- Обратная связь сохраняется на наблюдении, общий для отчётов вывод получает одну текущую оценку. История правок оценки не ведётся.
- До внешнего развёртывания нужны HTTPS reverse proxy, `COOKIE_SECURE=true`, точные `ALLOWED_ORIGINS`, `DEMO_MODE=false`, реальные пользовательские процессы, резервное копирование и отдельная оценка требований к данным. Для публичного показа синтетической демоверсии сохраняйте её изоляцию от реальных данных.
