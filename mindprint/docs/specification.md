Предлагаю сделать **MINDPRINT AI** как полноценную веб-платформу с двумя интерфейсами: пациента и психолога.

Для чемпионата важно показать не просто чат с ИИ, а весь процесс: **психолог назначает упражнения → пациент общается с ИИ → система анализирует изменения → психолог получает аналитику и корректирует рекомендации.**

Ниже готовое ТЗ, которое можно целиком передать Codex.

**Важный момент:** GigaChat используется только для демонстрации. Поскольку по условиям чемпионата внешние API запрещены, в презентации целевой архитектурой будет собственная LLM на RTX 5090. Для прототипа используем GigaChat на синтетических данных, а архитектуру сразу делаем независимой от поставщика ИИ.

# Техническое задание: MINDPRINT AI

## 1. Общая информация

**Название:** MINDPRINT AI

**Тип продукта:** AI-powered Mental Health Platform.

**Концепция:** платформа сопровождения пациентов между консультациями с психологом, использующая искусственный интеллект для эмоциональной поддержки, выполнения терапевтических заданий и анализа динамики психологического состояния.

**Позиционирование:**

> MINDPRINT AI — персональный ИИ-компаньон пациента, поведение которого настраивает его психолог.
>
> Система помогает пациенту между консультациями, анализирует изменения эмоционального состояния и предоставляет психологу структурированную аналитику.

### Главная идея

Психолог видит пациента приблизительно один час в неделю. Остальное время пациент остаётся без систематической поддержки и наблюдения.

MINDPRINT AI связывает эти периоды, создавая непрерывный цикл взаимодействия.

```text
Психолог
   │
   ▼
Назначает упражнения и цели
   │
   ▼
Пациент взаимодействует с ИИ
   │
   ▼
ИИ оказывает поддержку
и помогает выполнять упражнения
   │
   ▼
Система анализирует историю
и динамику состояния
   │
   ▼
Психолог получает аналитику
   │
   ▼
Корректирует план сопровождения
```

Главное отличие от стандартного ИИ-чатбота: система учитывает рекомендации психолога и индивидуальную историю пациента.

### Принципиальное требование

Архитектура должна позволять **заменить GigaChat на локальную LLM без изменения бизнес-логики приложения**.

Реализовать абстракцию `AIProvider`.

```python
class AIProvider(ABC):

    @abstractmethod
    async def chat(
        self,
        messages: list,
        context: dict
    ) -> str:
        pass

    @abstractmethod
    async def analyze_entries(
        self,
        entries: list
    ) -> dict:
        pass
```

Реализации:

- `GigaChatProvider` — для демонстрационной версии.
- `LocalLLMProvider` — интерфейс для будущего локального инференса.

Переключение через переменную окружения:

```env
AI_PROVIDER=gigachat
```

Для `LocalLLMProvider` пока достаточно подготовить интерфейс и конфигурацию подключения к локальному серверу. Не нужно реализовывать обучение модели.

# 3. Интеграция GigaChat

Для прототипа использовать Sber GigaChat API.

Конфигурация находится в `backend/.env`:

```env
GIGACHAT_CREDENTIALS=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Pro

AI_PROVIDER=gigachat
DEMO_MODE=true
```

### Требования

1. Использовать официальный Python SDK GigaChat.
2. Все запросы к модели выполнять исключительно через FastAPI.
3. Не передавать ключи API на frontend.
4. Не сохранять ключи в репозитории.
5. Добавить `.env` в `.gitignore`.
6. Создать `.env.example` без секретов.
7. Предусмотреть обработку ошибок API.
8. Сохранять контекст предыдущих сообщений.
9. Реализовать таймауты запросов.
10. Добавить индикатор генерации ответа.

Если GigaChat недоступен, интерфейс должен показывать понятную ошибку. Для автономной демонстрации предусмотреть отдельный mock-режим с заранее подготовленными ответами.

**Важно:** в GigaChat передавать исключительно синтетические демонстрационные записи. Реальные дневники пациентов, персональные данные и медицинская информация не должны направляться во внешнее API.

# 8. Therapy Protocol Engine

**Это ключевая инновационная функция MINDPRINT AI.**

Необходимо реализовать механизм, при котором психолог может управлять поведением ИИ для конкретного пациента.

### Как это работает

Психолог открывает профиль пациента.

Переходит на вкладку:

**«План сопровождения»**

Там он может:

1. Указать основные темы терапии.
2. Добавить цели на неделю.
3. Назначить упражнения.
4. Определить частоту напоминаний.
5. Выбрать разрешённые сценарии взаимодействия.

Например:

```json
{
  "patient_id": 1,
  "therapy_focus": [
    "тревожность",
    "страх оценки",
    "рабочий стресс"
  ],
  "goals": [
    "отслеживать автоматические мысли",
    "фиксировать триггеры тревоги"
  ],
  "allowed_exercises": [
    "thought_diary",
    "breathing",
    "daily_reflection"
  ],
  "reminders_enabled": true
}
```

Этот объект должен автоматически учитываться при генерации ответов ИИ.

### Принцип работы

При обращении пациента backend собирает контекст:

```text
SYSTEM INSTRUCTIONS
        +
PATIENT PROFILE
        +
THERAPY PLAN
        +
RELEVANT HISTORY
        +
CURRENT MESSAGE
        │
        ▼
      LLM
        │
        ▼
   AI RESPONSE
```

Пациент не должен иметь возможность изменять терапевтические назначения через чат.

### AI-анализ дневника

После сохранения записи система отправляет текст в AI-модуль.

ИИ извлекает структурированные наблюдения:

```json
{
  "emotions": [
    "тревога",
    "грусть"

    "работа",
    "отношения"
  ],
  "observations": [
```

Структура должна валидироваться через Pydantic.

Необходимо сохранять исходную запись, результаты анализа и ссылки на фрагменты текста, на основании которых были сделаны выводы.

Если данных недостаточно, модель должна возвращать отсутствие наблюдения, а не придумывать его.

# 12. Система упражнений

Создать библиотеку упражнений.

Для MVP реализовать три сценария.

### Упражнение 1. Дневник мыслей

2. Какая мысль возникла?
3. Какие эмоции ты испытал?
4. Какие есть факты за и против этой мысли?
5. Как можно иначе посмотреть на ситуацию?

### Упражнение 2. Дыхательная практика

### Упражнение 3. Рефлексия дня

ИИ задаёт вопросы:

- Что сегодня было самым сложным?
- Что получилось хорошо?
- Что помогло справиться?
- Что хотелось бы обсудить с психологом?

Сохранять результаты в истории упражнений.

**Важно:** упражнения являются демонстрационными сценариями и должны быть доступны пациенту только в рамках согласованного плана. Не представлять их как доказанно подходящие каждому пользователю.

# 13. Безопасность взаимодействия

Поскольку приложение относится к сфере психического здоровья, необходимо предусмотреть специальные ограничения.

### Safety Engine

Создать отдельный модуль обработки потенциально опасных сообщений.

Примеры:

- Сообщения о намерении причинить себе вред.
- Упоминания непосредственной угрозы жизни.
- Запросы об изменении дозировки лекарств.
- Запросы на постановку диагноза.

В таких ситуациях обычная генерация ответа не должна быть единственным механизмом реагирования.

Для явно опасных запросов предусмотреть заранее определённые сценарии.

Например, при сообщении о непосредственной угрозе жизни:

- Поддерживающий ответ без осуждения.
- Рекомендация немедленно обратиться за экстренной помощью.
- Предложение связаться с близким человеком или специалистом.
- Отображение экстренного номера 112 для России.

Не обещать, что психолог получит уведомление или немедленно ответит, если такая договорённость отсутствует.

Реализовать визуальное предупреждение:

«MINDPRINT AI не является службой экстренной психологической помощи».

Важно предусмотреть, что автоматическое обнаружение кризисных ситуаций несовершенно и требует отдельной валидации.

# 17. Демонстрационные данные

**Это критически важно для презентации.**

После запуска приложения должен существовать заполненный тестовыми данными профиль пациента Александра.

Создать синтетическую историю за 14 дней.

Сценарий:

**Дни 1–4**

Относительно стабильное настроение.

**Дни 5–8**

Появляются переживания, связанные с работой.

**Дни 9–11**

Пациент чаще упоминает проблемы со сном и тревогу.

**Дни 12–14**

Психолог назначает упражнение по работе с автоматическими мыслями. Пациент начинает его выполнять.

В демонстрационной аналитике должны отражаться именно эти события.

### Демонстрационный сценарий чемпионата

Необходимо обеспечить следующий пользовательский путь.

**Шаг 1.**

Открываем кабинет психолога.

Показываем пациента Александра и его эмоциональную динамику.

**Шаг 2.**

Психолог назначает упражнение «Дневник мыслей».

**Шаг 3.**

Переключаемся в кабинет пациента.

Пациент пишет ИИ:

«Мне снова очень тревожно из-за работы. Кажется, что начальник хочет меня уволить».

**Шаг 4.**

ИИ учитывает назначенное упражнение и предлагает выполнить его.

**Шаг 5.**

Пациент проходит несколько шагов упражнения.

**Шаг 6.**

Возвращаемся в кабинет психолога.

Видим обновлённую информацию о выполнении задания.

**Шаг 7.**

Генерируем аналитический отчёт с указанием источников наблюдений.

Это должен быть настоящий работающий сценарий с сохранением данных в PostgreSQL, а не набор статических страниц.

# 21. Критерии готовности

Проект считается готовым к демонстрации, если:

1. Приложение запускается через Docker Compose.
2. Есть два работающих интерфейса: пациент и психолог.
3. Можно войти под демонстрационными аккаунтами.
4. Пациент может написать сообщение ИИ.
5. GigaChat отвечает с учётом истории и терапевтического плана.
6. Психолог может назначить упражнение.
7. Пациент может выполнить упражнение.
8. Результат отображается в кабинете психолога.
9. Эмоциональный дневник сохраняет записи.
10. Аналитика показывает динамику на основе сохранённых данных.
11. ИИ может сформировать объяснимую сводку.
12. Можно переключить AI Provider через конфигурацию.
13. На сайте работает форма листа ожидания.
14. Основной демонстрационный сценарий работает без ручного изменения базы данных.

**Необходимо реализовать работающий продукт, а не только frontend-макеты.**

Если требуется упростить разработку, сокращать второстепенные функции, сохраняя основной пользовательский сценарий.

## Что особенно важно показать на чемпионате

Я бы сделал акцент на трёх экранах.

**1. Интерфейс общения с ИИ**

Пациент пишет о своих переживаниях. ИИ не просто отвечает универсальными советами, а знает назначенные психологом упражнения.

**2. Настройка ИИ психологом**

Психолог управляет тем, какие упражнения предлагает ИИ, какие цели отслеживаются и какая информация будет отображаться в аналитике.

**3. Аналитическая панель**

ИИ превращает две недели неструктурированных записей в понятную картину изменений с временной шкалой, графиками и объяснениями.

### Главный WOW-момент презентации

На экране психолог назначает упражнение. Затем вы переключаетесь на пациента и отправляете сообщение в чат. ИИ предлагает именно это упражнение. После выполнения вы возвращаетесь к психологу и видите результат.

**Вся последовательность должна проходить в реальном времени.**

Это наглядно демонстрирует, что MINDPRINT AI — не просто обёртка над GigaChat, а специализированная система с собственной бизнес-логикой, аналитикой и механизмом взаимодействия психолога и пациента.

И ещё один принципиальный момент для защиты: **не называйте демонстрационную версию с GigaChat реализацией закрытого контура**. На слайде архитектуры честно показывайте целевую локальную Qwen3 14B на RTX 5090, а GigaChat представляйте как временный инструмент проверки UX и пользовательских сценариев.
